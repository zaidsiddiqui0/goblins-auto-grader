## Files (about this many)
- `web/index.html`, `web/main.tsx` (router), `web/api.ts` (a typed fetch wrapper that imports types from `../shared/schema.ts`, saves teacher tokens in localStorage keyed by assignment id, and saves student submission tokens by submission id), `web/styles.css` (one file, no CSS framework), and page components in `web/pages/*.tsx`. Keep shared bits in `web/ui.tsx`.

## Routes
- `/` is the landing page with two clear actions: "Create an assignment" (teacher) and "Enter class code" (student, with a 6-char input). It also lists "Your assignments" from localStorage.
- `/new` is the teacher setup wizard. Show a visible stepper: **1 Questions → 2 Rubric → 3 Share**.
  - Step 1: a title, then either upload a PDF (`/api/extract`) or paste the text and click "Split into questions" (client-side numbered-line split is fine), or add questions manually. Each question card has an editable prompt and an optional "Answer key / teacher notes" field, and supports add/remove. Then "Save & continue", which calls POST /api/assignments and navigates to `/t/:id`.
- `/t/:id` is the teacher assignment page, and the stepper continues here.
  - No approved rubric yet: a "Generate rubric" button with a loading state (it takes up to about 30s). Show a short notice: "The rubric is generated from your questions only, before any student work is seen."
  - **Rubric editor**: for each question, show the prompt, editable expected answer, and an answerSource badge (inferred answers get a highlighted "Check this" label). Criteria appear as rows with an editable description and points, plus add/remove. The question max is shown as the computed sum. Partial credit, alternatives, and common mistakes are editable textareas (one item per line for the lists). needsReview questions show their reviewNotes in a callout. The total points appear in a sticky footer with the actions "Save draft" and "Approve & publish". Approving opens a confirm dialog: "Lock rubric v{n}? Submissions will be graded with this version." If any needsReview questions remain, the dialog lists them.
  - After approval: a share panel with the big access code, a copyable `/s/CODE` link, and a "Copy" button. The rubric shows read-only with "v{n} approved {date}", and an "Edit rubric (creates v{n+1})" action. Existing grades keep their version, so say that.
  - **Class report**: status counts (queued, processing, completed, failed) and a table with student, status pill, score/max, needs-review flag, rubric version, and submitted time. It polls every 3s while anything is non-terminal. Clicking a row opens the submission detail (a drawer or `/t/:id/s/:sid`) with the uploaded images, typed answers, transcription (with uncertain parts flagged), per-question criteria awards and rationale, feedback, the model and version used, "Retry" if failed, and "Override score" (number plus note). Empty state: "No submissions yet. Share code ABC123 with your class."
- `/s/:code` is the student page. It shows the title, a name input, and each question with a textarea answer. Optionally the student can attach photos or a PDF of their work, validated client-side (types and sizes from API.md), with thumbnails and the ability to remove them. Submit is disabled while sending. Generate the idempotencyKey once per form with `crypto.randomUUID()` and reuse it on a network retry, so a double-click can't create two submissions. Use a multipart upload with progress (XHR upload.onprogress). Show clear errors (file too big, not accepting yet, network). On success, navigate to `/r/:submissionId`.
- `/r/:sid` shows the student's own result, using the token from localStorage. Status with a calm progress message, polling every 2s until terminal. Then the score, per-question feedback, and overall feedback. If needsReview, label it "Your teacher may review this grade." Failed: "We couldn't grade this automatically. Your teacher can see it." With no token: "This result isn't available on this device."

## Design
A calm, education-oriented look: a warm off-white background, one accent color (deep green or indigo), readable 16px+ type, generous spacing, rounded cards, and visible focus rings. It should be responsive down to 375px. Every input needs a label. Buttons must be real `<button>`s. Cover loading, empty, error, and success states everywhere. No dead buttons and no lorem ipsum. Add a small footer that says "Demo: grades are AI-assisted and may be wrong. Teachers can review and override."

`npm run typecheck` passes for web files and `npm run build` succeeds. If the server exists by then, smoke it with `npm run dev`. Otherwise just make sure it builds. Update State/History in ai-instructions.md (one line each), and end with a ≤15-line summary.
