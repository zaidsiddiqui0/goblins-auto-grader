# Task D: Close gaps vs the original take-home

The source of truth is now `docs/takehome.md` (the original brief). Read it, `ai-instructions.md`, and `shared/schema.ts`, then skim the existing `server/` and `web/` before changing anything. You own the whole repo for this task. Keep the existing architecture and patterns. No new deps. Don't git commit. Be token-efficient: read files once, and keep tool output short with `tail`/`grep`.

## Changes (in this order; run `npm run typecheck && npm test` after each)

1. **One problem at a time (brief #4).** Students submit **per question**, then see that question's score, then go to the next. At the end they see a summary.
   - Add a `students` table: id, assignment_id, name, pin_hash, token_hash, created_at, with `UNIQUE(assignment_id, lower(name))`.
   - Submissions become per question, with `student_id` and `question_id` and `UNIQUE(student_id, question_id)`. That natural key replaces idempotencyKey: a duplicate submit returns the existing submission (200). Keep `rubric_version_id` pinned at submit time.
   - The worker, reader, and grader handle ONE question. Send the grader only that question's rubric entry (fewer tokens). Scoring stays in code (`scoreGrade` works on a 1-question rubric slice).
   - Delete the old whole-assignment submission flow instead of keeping both. Update `shared/schema.ts`, `docs/API.md`, and the tests.
2. **Whiteboard (brief #3).** On each question, the main input is a `<canvas>` whiteboard. It needs pen, eraser, undo, clear, and 3 colours, uses pointer events (mouse, touch, stylus), and is responsive. Set `touch-action:none` on the canvas only. On submit, export it to PNG and send it as the image file. It should be blank by default. Also keep an optional "Type your answer" textarea and an optional "Upload a photo instead". The reader: whiteboard/photo → vision; typed only → no model call. Downscale the canvas export to ≤1000px on its long side (vision tokens scale with pixels).
3. **Cross-device persistence (brief #6).**
   - Student: they join with class code + name + a 4-digit PIN they choose. Returning on any device means the same code + name + PIN, which restores the session token and their progress. Store the PIN hashed. After 5 wrong PINs per student, lock for 10 minutes.
   - Teacher: after creating an assignment, show a "Private teacher link" `/t/:id#k=<token>`. The token sits in the URL fragment so it never reaches the server or logs. Show it with a copy button and the note "Bookmark this to open your class on any device." Opening that link stores the token in localStorage and strips the fragment. Also show the link on the teacher page.
4. **Teacher report (brief #5).** A grid with one row per student. It shows progress (answered k/N), total score, and a per-question cell (score, or a status pill). Clicking a cell opens that submission's detail. Keep retry/override. It polls while anything isn't terminal.
5. **Growth CTA.** On the teacher page, add a small, non-pushy card: "Want live feedback and analytics for your students? Assign this in Goblins →" linking to `https://goblinsapp.com`. Add it to the student summary too ("Made with Goblins").
6. **Load test.** Update `scripts/loadtest.ts` to the new API. Each simulated student joins, then submits questions **sequentially with seeded think-time** (`--think-ms`, default 2000 ±50%). That's a realistic testing-day spike: a class works through it in the same window. Keep all the integrity checks: lost, duplicated, and stuck counts, plus a duplicate replay of the same (student, question). Report per-submission latency.
7. **Accuracy eval (brief: "how accurate w/ cheaper models?").** Write `scripts/eval.ts` with a fixed, labeled set in `scripts/eval-set.json`. Use 3 questions with teacher answer keys and a fixed rubric (hand-written in the file, so there's no rubric generation cost), and about 15 typed student answers with a human `expectedScore` (a mix of correct, partially correct, wrong, and alternative methods). It calls the real grader directly (not over HTTP) for each `--model` (repeatable flag), then prints exact-match %, mean absolute error, cost, and p50 latency per model, and writes JSON to `loadtest-results/`. Refuse to run without `LLM_MODE=real`. **Don't run it**; Opus will.
8. **Tests to add or keep:** the integration test covers join → submit q1 → duplicate submit returns the same id → completed → wrong PIN rejected → rejoin with the right PIN returns progress → another student's token gets 404. Add a test that editing an approved rubric creates v2 and the old grade keeps v1. Add a test that `/api/extract` on a tiny generated PDF returns questions; build the PDF bytes inline as a minimal valid PDF string.
